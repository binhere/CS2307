Kiến trúc hệ thống

Thuật ngữ và ký hiệu

Pipeline
chuỗi bước xử lý nối tiếp: đầu ra của bước trước là đầu vào của bước sau.
Bronze · Silver · Gold
ba tầng dữ liệu (kiến trúc medallion): thô, đã làm sạch và làm giàu, sẵn sàng nạp vào cơ sở dữ liệu.
OSM · OSRM · POI
OpenStreetMap (bản đồ mở); OSRM tính quãng đường lái xe trên OSM; POI là địa điểm tiện ích như trường, chợ, bệnh viện.
NFC
một dạng chuẩn hóa Unicode của chữ có dấu; tên ảnh phải cùng dạng NFC thì mới khớp với key trong catalog.
Embedding
vector số biểu diễn nghĩa của một đoạn văn (ở đây 1024 chiều); hai đoạn có nghĩa gần nhau thì có vector gần nhau.
Ollama · qwen3
Ollama chạy model embedding qwen3-embedding:0.6b, trên GPU của máy phát triển hoặc CPU của server.
FTS · pgvector
full-text search: tìm theo từ khóa trong PostgreSQL; pgvector: phần mở rộng của PostgreSQL để tìm vector gần nhất.
Neo4j · Cypher
cơ sở dữ liệu đồ thị lưu quan hệ giữa tin, phường, đường, cụm vị trí và tiện ích; Cypher là ngôn ngữ truy vấn của Neo4j.
Object storage
kho lưu trữ tương thích S3 (MinIO khi chạy local), lưu ảnh tin đăng.
Next.js · FastAPI
framework của frontend (React, TypeScript) và backend (Python).
LLM · BYOK
mô hình ngôn ngữ lớn; bring your own key: người dùng tự nhập API key của nhà cung cấp LLM, server không lưu key.
LangGraph · Supervisor
LangGraph tổ chức chatbot thành một đồ thị các bước; Supervisor là bước LLM đầu tiên của mỗi lượt, chọn trò chuyện hay tư vấn.
ReAct · checkpoint
ReAct: vòng lặp lập luận, gọi công cụ (action), đọc kết quả (observation), lặp lại cho tới khi trả lời được; checkpoint: trạng thái hội thoại lưu lại cho lượt sau.
Ridge · RF · HistGB
ba model hồi quy được so sánh: Ridge (tuyến tính), Random Forest, HistGradientBoosting (gradient boosting trên cây quyết định); cả ba đều thuộc scikit-learn.
R² · RMSE · MAE · MAPE
hệ số xác định (càng gần 1 càng tốt); căn bậc hai của sai số bình phương trung bình; sai số tuyệt đối trung bình; sai số phần trăm tuyệt đối trung bình.
CI · GHCR
continuous integration: GitHub Actions tự động chạy test và build mỗi lần push; GitHub Container Registry lưu image container.
Tag main-<UTC>-<sha>
tên phiên bản của image, gồm thời điểm commit (giờ UTC) và 7 ký tự đầu của mã commit.
Deployment · CronJob
Deployment: service chạy liên tục, đổi tag image thì được cập nhật; CronJob: tác vụ chạy theo lịch.
Seed · digest
seed: image chứa catalog (tin, vector, đồ thị) và script nạp; digest: mã SHA-256 của nội dung, digest đổi thì nạp lại.
CRC-32 · range request
CRC-32: mã kiểm tra của từng ảnh trong file zip; range request: chỉ tải một đoạn byte, nên tải tiếp được khi kết nối bị ngắt.

giao diện (trình duyệt, Next.js) · xử lý (script, job, service) · dữ liệu lưu trữ (file, cơ sở dữ liệu, registry) · dịch vụ bên ngoài · khung nét liền = nơi chạy · khung nét đứt = các bước trong một API · mũi tên nét đứt = bước tùy chọn · mũi tên hai đầu = gọi và nhận kết quả

1. Tổng quan

Hệ thống chuẩn bị dữ liệu offline trên máy phát triển, đưa qua GitHub và chạy online trên máy chủ.

2. Pipeline dữ liệu

Pipeline chạy trên máy phát triển mỗi khi có dữ liệu mới; dữ liệu và vector được commit vào repository, ảnh được upload lên Google Drive.

3. Luồng huấn luyện

Chỉ model định giá được huấn luyện trong dự án, trên data/v3: 3.857 tin của catalog cộng 2.846 tin của dataset cũ, nên khác với 3.857 tin đang hiển thị trên site.

4. Triển khai và nạp dữ liệu

Push lên main sẽ kích hoạt build; frontend và backend tự cập nhật, còn seed và embedding được ghim tag bằng tay.

5. Luồng suy luận khi tìm kiếm

Mỗi câu hỏi đi qua năm bước; khi Neo4j, embedding service hoặc LLM không hoạt động, bước tương ứng được bỏ qua.

6. Luồng suy luận của tư vấn và các API khác

Công cụ search_properties chạy đúng luồng tìm kiếm ở mục 5; các API còn lại không gọi LLM.
